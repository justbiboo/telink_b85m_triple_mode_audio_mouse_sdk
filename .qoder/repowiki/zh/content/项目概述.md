## 简介
本项目为基于 Telink B85m 的三模音频鼠标 SDK，面向智能办公场景，提供 BLE 蓝牙、2.4G 无线和 USB 有线三种连接模式，并内置 AI 语音采集与实时上报能力。通过“鼠标端 + Dongle”协同架构，实现语音数据在三种工作模式下的高可靠传输，同时兼顾低功耗、稳定性与跨平台兼容性。

- 目标用户
  - 初学者：了解三模音频鼠标的整体概念、应用场景与基本使用方法。
  - 有经验的开发者：掌握音频链路、协议栈、USB/HID、OTA、Flash 保护与 PM 功耗管理等关键技术点。
- 技术目标
  - 统一音频采集与编码流水线，适配 BLE/2.4G/USB 三种通道；
  - 提供稳定可靠的配对、回连、多设备管理与 OTA 升级；
  - 优化报告率与 FIFO 流控，确保语音与鼠标移动互不干扰；
  - 完善 Flash 保护与低功耗策略，提升产品可靠性与续航。

## 核心组件
- 三模连接管理
  - 2.4G 无线：RF 分包上报语音数据，支持 ACK 与 FIFO 流控
  - BLE 蓝牙：自定义 GATT 服务 Notify 上报语音，MTU 协商与动态 UI 间隔
  - USB 有线：HID 上报鼠标与音频数据，可枚举为复合设备
- AI 语音链路
  - AMIC 模拟麦克风 → Codec/PGA → MSBC 编码（每帧 57 字节）→ 按模式分包/打包上报
  - 语音时长自适应控制（按电量限制单次开麦时长）
- 系统资源与安全
  - Flash 保护机制（HAL 层 + 回调注册），OTA 期间解锁/上锁联动
  - PM 功耗管理（suspend/deep/长睡眠、唤醒源、校准与电容配置）
- 工具链与版本
  - BLE SDK V3.4.2.8，平台 SDK V3.3.0（对外标注），工具链 TC32 ELF GCC4.3

## 详细组件分析

### 三模连接与切换
- 2.4G 模式
  - 语音分包：MIC_DATA_CMD 拆分为两包（29B + 28B），ACK 机制保障可靠性
  - FIFO 流控：超过阈值丢弃音频帧，避免阻塞
  - 报告率协同：开语音时降低鼠标报告率，保证带宽
- BLE 模式
  - 自定义 GATT 服务 Notify 上报语音，MTU size exchange 提升单包载荷
  - UI 通知间隔随连接间隔动态调整，提升稳定性
- USB 模式
  - HID 上报鼠标与音频数据，可枚举为复合设备
  - 报告率策略：关语音 1K，开语音 500 Hz（V0.2.5.3 起）

### AI 语音链路
- 采集与编码
  - AMIC 差分输入，Codec/PGA 放大，MSBC 编码输出 57B 帧
  - 可选 ADPCM/SBC/MSBC 预编译库
- 上报通道
  - 2.4G：分包上报，dongle 端按索引拼接
  - BLE：自定义服务 Notify
  - USB：HID 上报 63B 数组承载
- 流控与健壮性
  - dongle 端独立 FIFO，避免 Linux 系统下语音堵塞
  - 语音包索引机制防止丢包导致数据错位

### Flash 保护与 OTA
- Flash 保护
  - HAL 层 + 回调注册，统一加锁/解锁流程
  - 应用层初始化时全锁，OTA 期间临时解锁
- OTA 通道
  - BLE OTA：手机 App 经 BLE 连接升级
  - USB OTA：上位机通过 USB 升级
  - 2.4G OTA：鼠标经自定义命令包上报 OTA 数据/ACK
- 双块 Flash 方案（Dongle）
  - 分块写入、CRC32 校验、断点续传进度上报

## 故障排查指南
- 常见问题定位
  - 语音画线异常：检查报告率策略与 FIFO 流控（2.4G/USB）
  - Chromebook 睡眠唤醒问题：确认 BLE/USB 模式下的唤醒行为与报告率
  - 多设备配对冲突：检查回连状态与 FIFO 隔离
  - OTA 失败：确认 Flash 保护状态与 CRC32 校验结果
- 参考路径
  - 语音任务与开关：AAA_Public.c（ui_enable_mic / task_audio*）
  - dongle 音频接收：app.c（MIC_DATA_CMD 分支）
  - Flash 保护：hal_flash.c / flash_common.c
  - PM 配置：platform_init() 与 pm_* 接口
